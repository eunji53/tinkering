# 회의록 작성 프롬프트

STT 결과(`output/*_STT.txt`)를 Claude(또는 다른 LLM)에게 줄 때 아래 지시문을 함께 붙여넣으면,
`scripts/make_docx.*`가 바로 변환할 수 있는 구조의 회의록 마크다운을 받을 수 있습니다.

아래 `## 지시문` 아래 내용을 통째로 복사해서, STT 전사문과 함께 전달하세요.

---

## 지시문

첨부한 STT 전사문을 바탕으로 회의록 마크다운을 작성해줘.

### 형식 (이 구조와 제목 문구를 그대로 지킬 것 — docx 변환 스크립트가 제목으로 섹션을 인식함)

```markdown
---
회의명: (주제 / 참석 대상이 드러나는 제목)
일시: (YYYY년 M월 D일 (요일). 모르면 "확인 필요")
장소: (모르면 "확인 필요")
참석자: (전사문에서 확인되는 만큼. 소속·직책이 불확실하면 "확인 필요" 병기. 발언자 구분이 안 되면 "화자 구분 불가"라고 명시)
작성자: (비워두거나 이름 직접 입력)
---

# 1. 주요 논의 안건
- 안건 1
- 안건 2

# 2. 주요 논의 내용
## 가. (주제 1)
- 내용
## 나. (주제 2)
- 내용

# 3. 결정 사항 및 향후 일정
- 항목명: 내용 설명
```

- `#` / `##` 제목과 `1. 주요 논의 안건` · `2. 주요 논의 내용` · `3. 결정 사항 및 향후 일정` 문구는 절대 바꾸지 말 것.
- 2번 섹션 소제목은 `## 가. 주제명`, `## 나. 주제명` 형식. 소제목 순서 기호(가/나/다)는 그대로 적으면 됨.
- 3번 섹션은 `항목명: 내용` 형식으로 쓰면 docx에서 2열 표로 변환됨. 콜론이 없으면 전체가 "내용" 칸에만 들어감.

### 작성 규칙

- **스몰토크·인사말·근황 이야기·자리 정리·회의와 무관한 잡담은 회의록에 넣지 않는다.** 안건과 직접 관련된 내용만 정리한다.
- **"2. 주요 논의 내용"은 발언이 나온 시간 순서가 아니라 주제(안건)별로 묶어서 정리한다.** 회의 중간중간 흩어져 나온 같은 주제 발언은 하나의 소제목 아래로 모은다. 각 소제목은 되도록 "1. 주요 논의 안건"의 항목과 대응되게 한다.
- **지어내지 않는다.** 발언자·소속·참석자 이름을 추측하지 말고, 불확실하면 "확인 필요"라고 쓴다.
- STT가 잘못 들었거나 뜻이 불분명한 구간은 내용을 만들지 말고 `[청취 불명확]` 또는 `[내용 확인 필요]`로 표시한다.
- 화자 분리 정보가 없으므로, 명확히 구분되는 경우가 아니면 "A사 측" / "B사 측"처럼 큰 단위로만 구분하거나 화자 구분 없이 서술한다. 억지로 "참석자 1 / 참석자 2"로 나누지 않는다.
- 결정된 사항과 미결정(추가 확인 필요) 사항은 "3. 결정 사항 및 향후 일정"에서 구분해서 쓴다.
- 같은 문장이 STT에 비정상적으로 반복되면(`[반복 감지 N회 - 확인 필요]` 태그가 붙어 있을 수 있음) 실제 발언 횟수로 오인하지 않는다.

### 분량 옵션

- **"간략히"** 요청 시: 소제목당 2~4줄로 압축.
- **"상세히"** 요청 시: 아래를 추가로 포함.
  - 회의 목적 및 배경
  - 참석자별(또는 "A사 측"/"B사 측"별) 주요 의견
  - 확정된 사항 vs 추가 확인 필요 사항 구분
  - 제안된 기능·아이디어
  - 실행 업무 표(번호 · 업무 내용 · 담당자 · 기한 · 진행 상태 · 비고)
