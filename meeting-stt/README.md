# meeting-stt

회의 녹음 파일(m4a, mp3, wav 등)을 텍스트로 변환하고, 회사 표준 회의록 서식(docx)까지 만들어주는 도구입니다.
[faster-whisper](https://github.com/SYSTRAN/faster-whisper)를 사용하며, 로컬 GPU(CUDA)가 있으면 자동으로 활용하고, 없으면 CPU로 동작합니다.

## 전체 프로세스 (반복 작업)

회의가 끝날 때마다 아래 3단계를 반복합니다.

```
① 녹음 파일(.m4a 등)
      │  ./scripts/transcribe.sh
      ▼
② STT 텍스트 (output/*_STT.txt)
      │  Claude에게 STT 텍스트를 주고 "회의록 md 형식"으로 작성 요청
      ▼
③ 회의록 md (front matter + 1/2/3 섹션 고정 구조)
      │  ./scripts/make_docx.sh
      ▼
④ 회의록 docx (회의록 양식.docx 기반, 회사 표준 서식)
```

**1단계 – STT**: `./scripts/transcribe.sh <녹음파일>` 실행 (아래 "STT 변환" 참고)

**2단계 – 회의록 md 작성**: Claude Code에게 STT 결과 파일을 주고 아래 형식 그대로 작성해달라고 요청합니다. 이 구조를 지켜야 3단계 스크립트가 자동으로 변환할 수 있습니다. 복사해서 바로 쓸 수 있는 지시문은 [docs/회의록_작성_프롬프트.md](docs/회의록_작성_프롬프트.md) 참고.

```markdown
---
회의명: (회의 제목)
일시: (YYYY년 M월 D일 (요일))
장소: (확인 필요하면 "확인 필요"로 표시)
참석자: (확인 가능한 만큼, 불확실하면 "확인 필요" 명시)
작성자: (담당자명)
---
# 1. 주요 논의 안건
- 안건1
- 안건2

# 2. 주요 논의 내용
## 가. 주제1
- 내용1
- 내용2
## 나. 주제2
- 내용1

# 3. 결정 사항 및 향후 일정
- 항목명: 내용 설명
- 항목명: 내용 설명
```

- `#`, `##` 제목과 앞의 `1. 주요 논의 안건` / `2. 주요 논의 내용` / `3. 결정 사항 및 향후 일정` 문구는 그대로 유지해야 스크립트가 인식합니다.
- 2번 섹션의 소제목(가/나/다...)은 자동으로 순서대로 채워지므로, md에는 `## 가. 주제명`처럼 실제 소제목만 적으면 됩니다.
- 3번 섹션의 각 줄은 `항목명: 내용` 형식으로 쓰면 docx에서 표(항목/내용 2열)로 변환됩니다. 콜론이 없으면 전체 문장이 "내용" 칸에만 들어갑니다.

**3단계 – docx 변환**: `./scripts/make_docx.sh <회의록.md>` 실행 (아래 "docx 변환" 참고)

## 왜 이 모델을 쓰는가

- 기본 모델은 **`large-v3`**로 설정되어 있습니다. Whisper 계열 모델 중 정확도가 가장 높은 등급이며, 로컬 GPU(RTX 5060 Ti, VRAM 8GB)에서 CUDA + float16으로 정상 동작하는 것을 확인했습니다.
- 속도가 더 중요한 경우 `--model medium` 또는 `--model large-v3-turbo` 등으로 바꿔서 실행할 수 있습니다(정확도는 다소 낮아질 수 있음).
- 한국어 회의 녹음을 기준으로 만들어졌으며 기본 언어는 `ko`이지만, `--language` 옵션으로 다른 언어도 지정할 수 있습니다.

## 설치

```bash
pip install -r requirements.txt
```

- Python 3.10 이상 권장
- NVIDIA GPU + 드라이버가 있으면 자동으로 사용합니다(별도 CUDA 툴킷 설치 없이 ctranslate2가 자체적으로 처리). GPU가 없거나 실패하면 자동으로 CPU(int8)로 전환됩니다.
- 최초 실행 시 모델 파일이 Hugging Face에서 자동 다운로드됩니다(수백 MB~수 GB, 인터넷 연결 필요). 이후에는 캐시된 모델을 재사용합니다.
- docx 변환에는 `python-docx`가 필요합니다 (`requirements.txt`에 포함).

## STT 변환

### 쉘 스크립트로 실행 (권장)

```bash
# 파일 하나
./scripts/transcribe.sh "/path/to/회의녹음.m4a"

# 여러 파일
./scripts/transcribe.sh "회의_1.m4a" "회의_2.m4a"

# 폴더 전체 (폴더 안의 지원 확장자 파일을 모두 찾아서 변환)
./scripts/transcribe.sh "/path/to/회의폴더"

# 모델/언어 등 옵션 추가
./scripts/transcribe.sh "회의녹음.m4a" --model medium --language ko
```

Windows에서는 Git Bash(또는 WSL)에서 실행하세요.

### 파이썬 스크립트 직접 실행

```bash
python src/stt_transcribe.py "회의녹음.m4a" --output-dir output
```

## 옵션

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `inputs` | (필수) | 오디오 파일 경로 또는 폴더 경로 (여러 개 지정 가능) |
| `--output-dir` | `output` | 변환 결과 저장 폴더 |
| `--model` | `large-v3` | Whisper 모델 크기 (tiny/base/small/medium/large-v3/large-v3-turbo 등) |
| `--language` | `ko` | 언어 코드 |
| `--device` | `auto` | `auto`(GPU 우선, 실패 시 CPU) / `cuda` / `cpu` |
| `--compute-type` | `float16` | 연산 정밀도 (CPU 사용 시 자동으로 `int8`로 조정됨) |

## 결과물

- `output/<원본파일명>_STT.txt` 형태로 저장됩니다.
- 각 줄은 `[시작시각 - 종료시각] 텍스트` 형식의 타임스탬프 포함 텍스트입니다.
- 같은 파일을 다시 변환하면 기존 결과를 덮어씁니다.
- `output/` 폴더는 `.gitignore`에 포함되어 있어 git에 커밋되지 않습니다(회의 내용은 민감정보일 수 있으므로).

## 지원 확장자

`.m4a` `.mp3` `.wav` `.mp4` `.aac` `.flac` `.ogg` `.wma`

## 알려진 한계 (STT)

- 화자 분리(diarization) 기능은 없습니다. 여러 명이 대화하는 녹음에서는 발언자 구분 없이 순서대로만 텍스트가 생성됩니다.
- 무음/잡음 구간에서 동일한 짧은 단어(예: "네")가 반복 생성되는 오류가 간혹 발생할 수 있습니다. 회의록 등 문서로 정리할 때는 원문을 그대로 신뢰하지 말고 이상하게 반복되는 구간은 확인이 필요합니다.

## docx 변환 (회의록 md → 회사 표준 서식)

`src/md_to_docx.py`는 위 "회의록 md 작성" 형식으로 쓰인 md 파일을 읽어, `회의록 양식.docx` 템플릿에 값을 채워 새 docx를 만듭니다.

```bash
./scripts/make_docx.sh "회의록.md"

# 템플릿/출력 경로 직접 지정
./scripts/make_docx.sh "회의록.md" --template "다른양식.docx" --output "결과.docx"
```

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `md_file` | (필수) | 입력 회의록 md 경로 |
| `--template` | `template.docx` | 회의록 양식(docx) 템플릿 — 직접 준비 |
| `--output` | md와 같은 폴더/이름 (`.docx`) | 출력 경로 |

### 변환 규칙

- 정보 표(회의명/일시/장소/참석자/작성자)와 부제목(회의명)을 md front matter 값으로 채웁니다.
- "1. 주요 논의 안건"과 "2. 주요 논의 내용"은 템플릿의 불릿(List Paragraph)/소제목(Heading 2) 스타일을 그대로 복제해서 항목 수만큼 반복합니다.
- "3. 결정 사항 및 향후 일정"은 **표(항목/내용 2열)**로 생성합니다. 템플릿 원본은 빈 줄 하나뿐이지만, 실제 사용 사례(0704 회의록)를 따라 표 형식으로 통일했습니다.
- 템플릿 파일 자체는 수정하지 않고, 매번 새 docx로 저장합니다.

## 알려진 한계 (docx 변환)

- md의 `#`/`##` 제목 문구가 정확히 일치해야 인식됩니다("1. 주요 논의 안건" 등 문구를 바꾸면 안 됨).
- 표/이미지 등 서식이 복잡한 md 문법은 지원하지 않습니다(제목 + 불릿만 지원).
- 참석자·장소 등 정보가 불확실할 때는 md에 "확인 필요"라고 적어 두면 docx에도 그대로 반영되므로, 최종 배포 전 사람이 한 번 검토하는 것을 권장합니다.
