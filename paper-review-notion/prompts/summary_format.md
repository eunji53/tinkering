# 논문 요약 형식

Claude Code로 정리할 때와, 나중에 API 스크립트(`src/generate_summary.py`, 예정)로 정리할 때 모두 이 형식을 쓴다.
형식을 바꾸려면 이 파일만 고친다.

## 입력

`output/<논문>_extract_<날짜>/` 폴더

- `full_text.md`: 정리된 본문 (그림·표·수식 자리 표시, 문장 속 수식은 `$...$` LaTeX)
- `extraction_report.md`: 그림·표·수식 목록과 캡션
- `figures/`, `tables/`, `equations/`: 이미지

## 출력

1. 로컬 사본: `output/<논문>_summary_<날짜>.md`
2. Notion "논문 리뷰" 데이터베이스에 한 행

## Notion 데이터베이스 속성

| 속성 | 내용 |
|---|---|
| 제목 | 논문 제목 (영문 원제) |
| 링크 | arXiv 등 논문 주소 |
| 연도 | 공개 연도 |
| 기관 | 저자 소속 |
| 태그 | 주제 태그 (없으면 새로 추가) |
| 3줄 요약 | 아래 3줄 요약을 각각 한 줄로 줄여 줄바꿈으로 구분 (🚀 / 💡 / 📈 각 한 줄) |
| 정리일 | 정리한 날짜 |
| 상태 | `읽을 예정` (처음 만들 때) |

## 페이지 본문 (한국어)

원칙: **기본 화면은 짧게, 자세한 내용은 접어 둔다.** 그림·표·수식은 따로 모으지 않고, 그 내용을 설명하는 자리에 넣는다.

맨 위에 저자·소속, 공개 시기, 논문·코드 링크를 목록으로 적은 뒤 아래 순서로 쓴다.

1. **3줄 요약** (펼친 상태): 🚀 무엇을 했나 / 💡 핵심 방법 / 📈 주요 결과. 각 1~2문장.
2. **용어 정리** (접힌 제목 블록): 핵심 용어 10~16개를 `| 용어 | 설명 |` 표로. 처음 보는 사람도 이해하게 쉬운 말로.
3. **배경과 문제 / 방법 / 실험 결과 / 한계 / 의의와 공개 자료** 섹션마다:
   - **기본 화면**: 핵심 2~4줄 요약. 그 섹션을 대표하는 그림·표 또는 수식은 최대 1~2개만 여기에 넣는다.
   - **"자세히 보기" 접기 블록**: 자세한 설명, 나머지 수식·그림·표, 세부 수치.
   - 수치는 본문·표에서 그대로 가져오고 근거 표·그림 번호를 괄호로 단다.
   - 수식은 이미지를 보고 LaTeX로 옮겨 `$$` 블록으로 넣고, 앞에 한 줄 설명, 끝에 원래 번호 `\quad (n)`.
   - 그림·표는 이미지로 넣고 캡션에 한 문장 설명.
   - 섹션별로 꼭 챙길 것:
     - **방법**: 제안 기법 외에 학습 방식(손실 함수, 데이터 처리)과 실제로 쓴 하이퍼파라미터를 "자세히 보기"에 표로 (재현할 때 필요).
     - **실험 결과**: 수치 결과뿐 아니라 저자가 강조하는 결론·교훈, 평가 설정(데이터, 평가 방식)과 그 한계, 데이터 누수 점검 같은 검증.
     - **의의와 공개 자료**: 논문의 기여·파급 효과(Broader Impacts), 공개한 코드·모델·데이터 링크.
4. **내 메모**: 빈칸.

Notion에서 접기 블록은 `<toggle heading="h2|h3">제목` 형식을 쓴다. 로컬 md 사본은 `<details><summary>자세히 보기</summary> … </details>`로 같은 구조를 만든다.

## 지킬 것

- **부록까지 모두 읽는다.** 학습 설정, 하이퍼파라미터, 추가 실험(ablation), 데이터 설명은 부록에만 있는 경우가 많다. 참고문헌 목록만 건너뛴다.
- 논문에 없는 내용을 지어내지 않는다. 수치·주장은 추출 텍스트와 대조한다.
- 논문 자체의 오류를 발견하면 고치지 말고 "논문에는 A로 적혀 있으나 실제로는 B"처럼 표시한다.
- 다 쓴 뒤 논문을 처음부터 다시 훑어 빠진 핵심 주장이 없는지 확인한다.
- 추출 텍스트가 깨진 수식은 `equations/` 이미지를 보고 옮긴다.
- 원본 파일(`input/`, `*_extract_*`)은 수정하지 않는다.
