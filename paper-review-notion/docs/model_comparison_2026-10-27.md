**입력 방식이 다르다는 점에 주의.** API 모델은 논문 전체(참고문헌 제외)를 한 번에 읽고 수식 이미지를 볼 수 있다.
Ollama 모델은 16K 컨텍스트에 맞춰 쪽별 메모만 보고 최종 요약을 쓰며 이미지를 보지 않는다. 따라서 결과 차이에는
모델 성능 외에 입력 방식 차이가 섞여 있다. qwen3.5:9b는 이미지 입력을 지원하므로 Ollama에도 이미지를 넘기는 개선 여지가 있다.

OpenAI 실행의 입력 토큰이 OpenRouter보다 1만 개 적은 것은 토크나이저 차이와, 당시 수식 이미지 첨부가 없었을 가능성
때문으로 보인다. 실행 기록에 첨부 수가 남지 않아 확정할 수 없다.

### '논문 자체 오류' 표시 검증

OpenRouter와 수동 요약이 표시한 원문 오류를 다시 확인했다.

- 1833 소인수분해: 원문은 "true factorization is 3×17×43". 3×17×43 = 2193, 1833 = 3×13×47 → **원문 오류 맞음** (계산으로 확인).
- 잔디 깎기 예시(OpenRouter만 지적): Guanaco의 결론은 "$582", 풀이 계산은 $528 + $30 = $558 → **불일치 맞음**
  (추출 텍스트 p.15로 확인, PDF 원본 이미지와는 대조하지 않음). 저자는 "풀이를 보여주면 정확하다"는 예로 들었다.

## 5. 결론과 제안

**qwen3.5:9b (로컬)** — gemma3:12b보다 4분 빠르고 표(Table 1·4·5·6)의 수치를 일부 옮겼지만, 형식이 크게 깨졌다.
섹션 제목이 H3로 내려가 한 접기 안에 몰렸고, 그림·수식이 하나도 없으며 '내 메모'를 채웠다. 사실 1건은 원문과 반대로 썼다.
한국어 조사 앞 띄어쓰기("GPT-4 를")와 한자("匹敵")가 섞이는 문제도 있다. 그대로 Notion에 올릴 수준은 아니다.

| 순위 | 모델 | 판단 |
|---|---|---|
| 1 | OpenRouter `anthropic/claude-sonnet-5.5` | **기본 모델로 제안.** 16개 사실 모두 포함·오류 없음, 원문 오류 2건까지 찾음. 1편당 약 $0.29(표시 단가 기준), 2분 남짓. 상세가 길어지는 점만 아래 방법으로 줄인다 |
| 2 | OpenAI `gpt-5.4-mini` | 빠르고 형식은 지키지만 수식·표·비교 대상 오류가 있어 **검토 없이 발행하기 어렵다** |
| 3 | Ollama `qwen3.5:9b` / `gemma3:12b` | 비용은 없지만 지금 방식(16K 텍스트 메모 → 요약)으로는 **개요 초안 수준.** 형식도 지키지 못해 발행용으로 쓰지 않는다 |

로컬 모델을 계속 쓰려면 모델보다 입력 방식을 먼저 바꿔야 한다: (1) 메모를 합칠 때 형식 문서가 컨텍스트 뒤로 밀리지
않도록 최종 단계 입력을 줄이거나, (2) num_ctx를 늘려 한 번에 읽히거나(qwen3.5는 262K 지원, 단 8GB GPU에서는
CPU 비중이 커져 더 느려짐), (3) 이미지를 함께 넘긴다. 이번에는 시도하지 않았다.

더 싼 API 후보로 OpenRouter 목록에 `anthropic/claude-haiku-5.5`(표시 단가 입력 $0.1 / 출력 $0.5)가 있다.
후순위로 정한 비교라 이번에는 실행하지 않았다.

### OpenRouter 결과를 형식에 맞게 줄이는 방법 (제안, 미적용)

1. `SYSTEM_PROMPT`에 상세(자세히 보기)의 상한을 둔다. 예: "섹션별 자세히 보기는 2,000자, 이미지 3개 이내.
   나머지 그림·표는 번호와 한 줄 설명만 쓴다."
2. 기본 화면은 "목록 4개 이하 + 대표 그림·수식 최대 2개"로 명시한다.
3. 생성 후 검사: 섹션별 기본 화면 줄 수·이미지 수를 세어 기준을 넘으면 경고한다(이번 비교에 쓴 점검과 같은 방식).
   요약을 다시 생성하지 않고 경고만 남기면 비용이 들지 않는다.

중요한 세부(하이퍼파라미터, 평가 설정, 데이터 누수 점검, 논문 오류)는 접힌 상세에 남겨야 하므로, 이미지 수와 길이만 제한한다.

### 그 밖에 발견한 것

- **태그가 모델마다 다르다** (OpenRouter: "양자화, 효율적 파인튜닝, …", OpenAI: "파인튜닝, 양자화, MMLU, …").
  Notion에는 없는 태그가 새로 생기므로, 프롬프트에 기존 태그 목록(LLM, Fine-tuning, Quantization, LoRA)을 주고
  가능하면 그중에서 고르게 하는 것이 좋다.
- gemma3는 제목을 한국어로 번역했다("QLoRA: 효율적인 양자화된 LLM 미세 조정"). 발행할 때 같은 논문의 기존 페이지를
  찾지 못해 중복 페이지가 생길 수 있다. 제목은 영문 원제를 그대로 쓰라는 규칙이 지켜졌는지 발행 전에 확인해야 한다.
