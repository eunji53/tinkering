아래 항목은 이번 발행에 적용한 요구사항이야. 위 완료 로그가 있으므로 새 실행 지시로 해석하지 마.

- 사용자가 **QLoRA의 저장된 GPT·Claude·Ollama 2종, 총 4개 결과 비교**를 선택했어. 추가 요약 생성 없이 기존 결과를 활용해. LightRAG의 새 모델별 요약 생성과 발행은 이번 범위에 포함하지 않아.
- 발행 대상은 OpenAI `gpt-5.4-mini`, OpenRouter `anthropic/claude-sonnet-5.5`, Ollama `gemma3:12b`, Ollama `qwen3.5:9b`야. 모델 이름은 당시 실행 JSON에 기록된 이름을 사용해.
- 기존 수동 QLoRA 페이지를 기준본으로 보존하고, 예를 들어 `QLoRA 비교 | GPT · gpt-5.4-mini`처럼 **모델을 구분하는 제목**으로 새 페이지 4개를 만들어줘. 같은 논문 링크가 있는 것은 이번 비교에서는 의도된 것이야. 중복 여부는 논문·모델·원본 실행 결과를 함께 확인하고, 같은 비교본을 반복 생성하지 마.
- 네 페이지 상단에 ‘모델 결과 비교용·오류 포함’과 생성 방식·기존 검토에서 발견한 문제를 표시해줘. 오류를 보고 비교하려는 목적이므로 이전의 ‘품질이 부족한 결과는 발행하지 않는다’는 일반 요약 기준을 이 비교용 발행을 막는 근거로 쓰지 마.
- 원본 `.md`와 실행 `.json`은 보존해. 사실 오류·누락·분량·자동 생성된 ‘내 메모’ 내용도 모델 결과로 식별해 보존하고, 사람의 검토 의견은 별도 구역에 써줘. 내용을 몰래 고치거나 다시 생성하면 비교가 달라져.
- Notion 전송을 위한 최소한의 표시 변환은 별도 사본에서만 하고 변경점을 기록해줘. 예를 들어 GPT의 없는 이미지 참조는 ‘원본 이미지 누락’ 표시로 대체할 수 있지만 올바른 표를 원래 생성한 것처럼 바꿔 넣지는 마. 이미지 경로가 사본 위치 때문에 깨지지 않도록 확인해.

- **LightRAG:** 요약·미리보기만 준비됐으며 실제 발행이나 모델별 새 비교 생성은 이번 범위 밖이었어. 새 요청을 받기 전에는 실행하지 마.
- **분량·형식 보강:** ‘상세 섹션당 2,000자·이미지 3개’, ‘기본 화면 목록 4개 이하 + 대표 그림·수식 2개’, 생성 후 형식 검사 등은 비교 문서의 **제안이며 아직 적용하지 않았어.** 기존에 확정된 요구사항으로 취급하지 마.
- **추가 로컬 입력 실험/Haiku 비교:** 모두 후순위 제안이고 실행하지 않았어. 현재 작업을 마치기 위해 기존 모델 비교를 다시 돌릴 필요는 없어.
- **Git 정리:** 기존 8개 파일은 문서를 포함해 `4d5ad21`로 커밋됐어. 연결 확인과 LightRAG 완료를 반영한 이 인계 문서는 그 이후의 로컬 변경이야. 새 LightRAG 자료는 Git 제외 대상이며 별도 코드 커밋은 필요하지 않아. 직접 커밋·푸시하지 마.

## 유지할 요약 형식

정확한 기준은 `prompts/summary_format.md`야. 다음 원칙을 유지해줘.

- 순서: 3줄 요약 → 용어 정리 → 배경과 문제 → 방법 → 실험 결과 → 한계 → 의의와 공개 자료 → 내 메모.
- 기본 화면은 섹션별 핵심 2~4줄, 대표 그림·표·수식은 최대 1~2개만. 상세 내용은 ‘자세히 보기’로 접어둬.
- 용어 정리는 쉬운 설명으로 10~16개, 접힌 상태로 제공해.
- 그림·표·수식은 해당 내용을 설명하는 위치에 넣어. 별도 모음으로 분리하지 마.
- 본문과 부록을 모두 검토하고 참고문헌 목록만 제외해.
- 방법에는 학습 방식·데이터 처리·하이퍼파라미터, 결과에는 핵심 교훈·평가 설정·데이터 누수 점검을 포함해.
- 수치와 비교 대상을 정확히 쓰고 근거 표·그림 번호를 붙여. 깨진 수식은 추출 이미지와 대조해.
- 논문 자체의 오류라는 판단도 원문과 확인한 근거를 구분해서 표시해. 이전 모델이 ‘오류를 찾았다’고 한 보고만으로 확정하지 마.
- 원본 PDF와 기존 추출 폴더는 보존해. `내 메모`도 보존해.

OpenRouter가 표시한 논문 내 불일치 중 두 건도 추가 점검됐어. 1833의 소인수분해는 `3×13×47`이고 논문에 적힌 `3×17×43`은 2193이므로 계산으로 확인됐어. `$582`와 풀이 과정의 `$528 + $30 = $558` 불일치는 추출 텍스트로 확인했지만 PDF 원본 이미지는 아직 확인하지 않았다고 보고됐어. 나머지 주장까지 전부 검증됐다고 확대하지 마.

이전 대화의 OpenRouter 비용 약 $0.29는 당시 단가를 이용한 추정이야. 실제 청구액이나 현재 가격으로 확정하지 마. 기존 모델 ID도 현재 가용 여부를 확인한 뒤 사용해줘.

로컬 실행은 GPU·CPU 혼합 사용으로 느렸다고 보고됐어. 현재 스크립트는 API에 본문과 수식 이미지를 보내고, Ollama는 16K 컨텍스트에서 텍스트 메모→합성 방식으로 이미지를 보내지 않아. **과거 OpenAI 실행에 수식 이미지가 실제 첨부됐는지는 기록이 없어 미확인**이라고 비교 문서에 적혀 있어. 토큰 수 차이만으로 첨부 여부를 단정하지 마. 비교에는 모델 성능뿐 아니라 입력 방식·환경 차이가 섞여 있어.

비교 문서의 OpenRouter 상세 이미지 개수는 본문에 11개/전체 13개, 별도 표에 전체 19개로 적혀 있어 집계 범위가 불명확했어. 10월 28일 원본 요약을 현재 발행기로 변환해 **전체 이미지 블록 19개**를 직접 확인했어. 접힌 상세에만 들어 있는 개수는 별도로 집계하지 않았으므로 전체 19개와 혼동하지 마.

## 환경과 현재 구현

- 키 파일은 `C:\Users\USER\Desktop\workspace\tinkering\.env`를 사용하기로 했어. 다른 저장소의 `.env`와 혼동하거나 복사하지 마.
- `OPENAI_API_KEY`, `OPENROUTER_API_KEY`는 기존 실행 기록에서 사용됐고, 최신 확인에서는 **`NOTION_TOKEN`, `NOTION_DATABASE_ID`도 설정돼 있어.** 기존 로더로 환경을 읽어 인증·데이터베이스 조회에 사용했으며 키 파일 내용이나 토큰 값은 출력하지 않았어.
- 기존 Claude의 Notion 연결과 직접 API를 호출하는 스크립트의 인증은 구분해줘. 직접 발행하려면 토큰과 데이터베이스 연결 권한이 필요해.
- 데이터베이스 ID `43884d81b1e643dc8a02ee2807f496b2`는 이번 API 조회에서 ‘논문 리뷰’로 확인됐어. 데이터 소스 ID와 혼동하지 마. 연결된 데이터 소스는 최신 연결 확인 결과에 기록해뒀어.
- 현재 코드 기본값: provider `openrouter`, 모델은 OpenRouter `anthropic/claude-sonnet-5.5`, OpenAI `gpt-5.4-mini`, Ollama `gemma3:12b`.
- API 출력 한도는 reasoning 토큰을 포함해 기본 40,000이야. 처음 16,000에서 요약이 잘려서 높였고, 현재 API 경로에는 `finish_reason`과 reasoning 기록·잘림 경고가 있어.
- Ollama 기본 컨텍스트는 16,384, `--think`는 기본 꺼짐이야.
- `--dry-run`으로 API 호출 없이 입력 구성을 확인할 수 있어.
- Qwen 짧은 테스트는 약 9 tok/s, GPU·CPU 혼합 사용으로 보고됐어. 당시 RTX 5060 Ti 8GB에서 다른 `qwen-local-lab` 작업도 자원을 쓰고 있었어. 다른 프로젝트 프로세스를 임의로 종료하지 마.
- Git Bash에서 한국어 인자를 보낸 테스트는 인코딩 문제로 추정되는 이상 응답이 있었고, Python으로 UTF-8 요청을 보내자 정상 응답했다고 보고됐어.
- 현재 생성기는 Ollama 메모를 메모리의 목록에만 모으고, **최종 요약을 받은 뒤에야 `.md`와 `.json`을 저장해. 중간 메모 재개 기능은 없어.** PC 종료·프로세스 중단으로 결과가 없다면 그 단계부터 자동 재개할 수 있다고 말하지 마.

## 구현된 Notion 발행기의 범위

- `src/publish_notion.py --summary <요약.md>`는 기본적으로 **미리보기만** 만들고 Notion API를 호출하지 않아. 별도 `--dry-run` 옵션을 붙일 필요가 없어.
- `--publish`로 실제 발행, `--database`로 데이터베이스 ID 지정, `--update-existing`으로 동일 제목 페이지 갱신을 선택하는 구조야.
- 제목·링크·연도·기관·태그·3줄 요약·정리일·상태 속성 및 제목·접기·표·그림·블록/인라인 수식 변환을 구현했어.
- 이미지 업로드는 Notion File Upload API를 사용하는 코드야. 없는 이미지·20MB 초과 등 문제를 감지하면 실제 발행을 중단하도록 작성됐어.
- 동일 제목이 있으면 기본적으로 중단해. 갱신 옵션을 쓰면 ‘내 메모’ 앞의 기존 본문을 지우고 새 내용을 넣으며, ‘내 메모’ 이하와 ‘상태’를 유지하도록 구현됐어.
- 3줄 요약에서 ‘크기보다’의 ‘다’를 문장 끝으로 오인한 문제와, 미리보기에서 인라인 수식이 빠져 보이던 문제를 수정했다고 보고됐어.
- 수동 요약의 미리보기는 접기 6개·이미지 6개·수식 블록 6개로 기존 Notion 페이지와 같은 구조였다고 보고됐어. 이 초기 점검 당시에는 실제 발행 전이었고, 이후 모델별 비교본 발행 결과는 최신 완료 로그에 기록했어.
- **로컬 테스트 통과와 실제 원격 갱신 성공은 별개야.** 현재 코드는 기존 본문을 삭제한 뒤 재삽입하므로, 실제 적용 전 실패 시 부분 반영과 메모 보존을 점검해줘. ‘내 메모’ 존재를 확인하기 전에 속성을 갱신하는 순서도 확인이 필요해.

## 이후 이어갈 때

### 1. 완료된 비교 결과에서 시작

- 위의 완료 로그와 비교 페이지 링크를 기준으로 현재 상태를 설명해줘. 인계 파일을 읽었다는 이유로 모델 실행이나 발행 스크립트를 다시 돌리지 마.
- 인증·데이터베이스 연결·새 페이지 생성·이미지 업로드는 성공한 기록이 있어. 새 오류가 없는 상태에서 같은 연결을 추가하거나 토큰을 다시 발급받으라고 하지 마. 키 값도 출력하지 마.
- 비교를 요청받으면 저장된 원본·실행 JSON·비교 문서와 이미 발행된 페이지를 활용해줘. Claude 결과가 기존 16개 점검 범위에서 가장 충실했다는 평가와, 입력 방식이 달라 통제된 모델 순위 실험은 아니라는 한계를 함께 설명해줘.
- 새 수정 요청이 없다면 완료된 비교 페이지 링크를 안내하는 것으로 충분해. 별도 유료 생성·추가 비교 실험·LightRAG 발행은 자동으로 시작하지 마.

### 2. 표시 개선을 요청받은 경우에만

- gemma·Qwen의 3줄 요약은 내용이 있으나 현 변환기가 인식하지 못한 것이야. 제목의 공백 변형과 목록 없는 세 줄을 구분해 처리하고, 새 문장을 생성할 필요는 없어.
- HTML 표·접기·본문 줄바꿈을 보완하더라도 원본 모델 결과와 표시용 변환을 구분해서 남겨줘. 사실 오류를 몰래 수정해 원래 모델 품질이 달라 보이게 하지 마.
- 모델 출력의 ‘내 메모’는 사용자의 실제 메모로 취급하지 마. **기존 수동 QLoRA 페이지의 본문·3줄 요약·메모·상태는 계속 보존해.**
- 현재 발행 스크립트는 같은 제목을 건너뛰는 방식이라 표시 개선에 그대로 재실행하면 수정이 적용된다고 보장할 수 없어. 기록된 페이지 ID로 대상을 식별하고 요청받은 변경만 수행해줘. 기존 발행기의 삭제→재삽입 갱신 경로는 별도 위험이 남아 있으므로 무조건 `--update-existing`을 쓰지 마.
- 변경 후에는 해당 부분을 다시 읽어 검증하고, 데이터 확인과 화면 확인을 구분해 보고해줘. 전체 재발행이나 다른 모델 재실행은 필요하지 않아.

### 3. 선택적인 형식 보강

- 비교 문서의 상세 길이·이미지 수 상한과 생성 후 검사, 기존 태그 사용 유도는 **미적용 제안**이야. 기존 확정 형식과 구분하고 필요한 개선만 다뤄줘.
- 길이를 줄이더라도 학습 설정·하이퍼파라미터·평가 설정·데이터 누수 점검 같은 핵심 내용을 없애지 마.
- 로컬 모델의 입력 방식 개선, 컨텍스트 확대, 이미지 첨부, Haiku 추가 비교는 후순위 제안이야. 이번 비교 발행은 완료됐으므로 새 요청 없이 시작하지 마.
